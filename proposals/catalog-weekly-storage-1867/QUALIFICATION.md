## Failing cases to write first

- Strict intent accepts only kind/catalog/required nullable organization/weekly schedule/timezone; rejects account/actor/artist/prompt/model/extra fields, malformed IDs, absent null workspace, unsupported cadence. Legacy task schemas/Trigger flows unchanged.
- Exact principal/scope roundtrip. Reject partial principal unions, fabricated owner, recipient unequal to effective account, invalid timezone/counter, null checks and unsafe JSON strings. Immutable columns and revisions reject update/delete/TRUNCATE for service/browser roles.
- Create concurrency: same actor/request/input gives one task/revision/receipt; changed input under key fails; two request IDs same scope create one schedule and conflict without adopting creator; same names/different catalog IDs remain distinct; personal and self-org scope remain distinct; disabled still dedupes; archive/recreate has distinct ID/history.
- CAS edit/disable/enable/archive concurrency and rollback: archive while enabled must fail; successful disable and later archive require separate expected revisions/receipts; atomic parent+revision+receipt; stale expected revision denied; changed-key replay denied; replay after newer revision returns old receipt, never old state as current; current authorization still required for readback. Scope/principal/recipient edits fail; other workspace member can emergency-disable only if selected policy passes, never enable/edit/take over. Lost/revoked creator leaves disabled dedupe slot occupied; replacement fails explicitly until separately authorized archive-only recovery exists.
- API-key current lookup: metadata-only by exact original ID; expired/deleted/reassigned/malformed/missing key hash denied; null expiry allowed; query errors block; no raw credential/hash output. Same-ID recreation/rotation is a qualification blocker until concrete immutable-identity policy is proven, not a green mock assumption.
- Privy app/issuer/subject mismatch, missing OAuth binding, null tombstone, ambiguous email mapping, subject/account change and unavailable current revocation check deny unattended execution. Do not create a binding from stored emails; no reuse of captured JWT. A present binding alone must not make tests pass as execution authority.
- Original actor is captured before any generic override logic; v1 rejects actor/effective inequality for every workspace, even when admin/shared-org policy would otherwise allow it. Personal self-only; exact-org membership for actor and effective; different org visibility denied; catalog transfer/link removal/account deletion/membership revocation before confirmation/claim/retry/commit denied. Broad cron/service/admin credential never substitutes original principal. DB lock/removal races show transaction admission boundary, not remote cancellation.
- Due claim concurrency: duplicate scans/task IDs/worker retries create one occurrence, advance cursor once; wrong returned ID/disabled/mismatched revision fails before effect; edit around same due instant cannot bypass unique occurrence key. Dispatch claim exact replay never starts twice. Response loss after claim or start is ambiguous, not automatically retried. Bind requires original attempt/run; no stale lease stealing.
- Weekly timezone: ordinary week, UTC offset, spring nonexistent local time, fall repeated local time, runtime/database zone disagreement, invalid zone; chosen skip/first policy, one local occurrence. Only the current UTC due minute may be claimed under the proposed no-catch-up runtime detail; older due slots emit skipped receipts and advance without send. This detail requires explicit runtime qualification after the disabled-only prototype. Create/re-enable/edit choose future instant; no catch-up burst. Pagination is stable and bounded under concurrent cursor updates.
- Catalog reader qualification belongs to Catalog: current exact catalog_songs, overlapping catalogs, multiple/non-roster/creator-less songs, deterministic complete pages, concurrent membership changes, empty/oversized catalogs, count mismatch. No artist discography or first-catalog substitution. Existing observation helpers preserve missing vs zero and comparable periods.
- Email/report effects blocked until current verified recipient/consent and resource restriction contracts exist. No generic email list or mutable prompt grants scope. Before any effect/retry, reauthorize; verify acknowledgement before completion. Ambiguous send cannot become automatic resend. Side-effect admission vs later disable/revoke is explicit in tests and docs.
- Legacy GET/PATCH/task worker still reads only scheduled_actions; new records cannot be downgraded by old PATCH. No new Trigger job, no modifying legacy timezone source of truth. New unified list, if later selected, must use discriminated kinds and exact-kind mutation dispatch.

## Rollout / rollback (separate authorization)

Proposed order after gates: approved additive DB change → generated type refresh and wrappers → disabled API capability → mocked/native acceptance → separately approved enablement/cron registration. No backfill of legacy prompts/artist IDs into catalog scopes. No schedule becomes enabled by migration default, deploy, navigation or a background data repair.

Rollback runtime first: disable catalog capability and new cron entry; atomically disable schedules/revision-bump; block new effect admissions; inspect original occurrences and reconcile any already-started workflows without automatically resending/cancelling providers. Preserve schedules, immutable revisions, mutation receipts and outcomes. Revert route/UI exposure and retain additive tables; legacy scheduled_actions/Trigger behavior remains unchanged throughout.

Removing schema is not ordinary rollback: require separate retention/export decision, evidence that no workflow references remain, explicitly scoped removal of only new RPC grants/functions/tables. Never blanket-drop CASCADE into shared accounts/catalogs or delete receipts to reset idempotency. In disposable tests only, teardown may remove the new objects after validating an explicit rollback script; no such script is shipped in this proposal.
